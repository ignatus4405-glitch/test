# Синхронизация времени Windows Server через NTP

`Sync-Time.ps1` настраивает встроенную службу времени Windows (`W32Time`) для работы с NTP-серверами. Скрипт включает автоматический запуск службы, сохраняет серверы и запускает синхронизацию. Дальнейшую периодическую синхронизацию выполняет сама служба Windows.

## Требования

- Windows Server с Windows PowerShell 5.1 или PowerShell 7 для Windows.
- Запуск PowerShell **от имени администратора**.
- Разрешение имён DNS (если используются имена серверов) и доступ к NTP-серверам по UDP/123. Разрешите исходящий трафик и ответы; W32Time также использует UDP/123 как исходный порт.
- Для публичных серверов нужен доступ в интернет. Обычный публичный NTP не аутентифицирован: при необходимости используйте доверенные серверы организации.

## Запуск на автономном сервере

Откройте PowerShell от имени администратора в папке со скриптом и выполните:

```powershell
.\Sync-Time.ps1
```

По умолчанию используются `0.pool.ntp.org`–`3.pool.ntp.org`. Чтобы указать свои серверы, передайте их отдельными элементами массива; флаг NTP `0x8` скрипт добавит сам:

```powershell
.\Sync-Time.ps1 -NtpServers 'time.cloudflare.com','time.google.com','time.windows.com'
```

Если локальная политика выполнения запрещает запуск скачанного скрипта, проверьте его содержимое и при необходимости разрешите запуск **только в текущем процессе PowerShell**:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\Sync-Time.ps1
```

Политики, заданные через Group Policy, могут иметь более высокий приоритет. Скрипт не меняет часовой пояс.

## Сервер в домене Active Directory

Обычно участники домена и контроллеры синхронизируют время по иерархии AD; внешний источник обычно настраивают только на PDC-эмуляторе **корневого домена леса**. Поэтому на доменном сервере скрипт по умолчанию останавливается без изменений.

Перед изменением убедитесь, что вы на нужном сервере. Узнать PDC корневого домена леса можно без модуля Active Directory:

```powershell
([System.DirectoryServices.ActiveDirectory.Forest]::GetCurrentForest()).RootDomain.PdcRoleOwner.Name
```

Только после проверки роли, если политика организации разрешает внешний NTP, запустите на этом сервере:

```powershell
.\Sync-Time.ps1 -AllowDomainJoined -MarkReliable
```

`-AllowDomainJoined` явно разрешает переход с доменной иерархии на список NTP-серверов. `-MarkReliable` объявляет сервер надёжным источником времени для домена; скрипт проверяет наличие роли PDC, но **не проверяет, является ли домен корневым в лесу**. Без этого ключа существующая настройка надёжного источника не меняется. Групповые политики могут переопределить локальные настройки; после переноса роли PDC конфигурацию нужно проверить на новом владельце.

## Проверка и устранение ошибок

Скрипт показывает текущий источник и состояние службы. При необходимости выполните:

```powershell
w32tm.exe /query /source
w32tm.exe /query /status
w32tm.exe /query /peers
w32tm.exe /query /configuration
```

Проверьте, что текущий источник — нужный NTP-сервер, а не локальные часы или нежелательный поставщик времени. Если немедленная синхронизация не удалась, скрипт выполнит до трёх попыток и завершится с ошибкой. Настройки, уже применённые к службе, при этом сохраняются; проверьте DNS, доступность серверов, UDP/123, групповые политики и журнал **System** с источником **Time-Service**. На виртуальной машине также проверьте настройки синхронизации времени с хостом.

Чтобы вернуть обычный доменный сервер или не являющийся корневым PDC контроллер к иерархии AD:

```powershell
w32tm.exe /config /syncfromflags:domhier /update
w32tm.exe /resync /rediscover
```

Эти команды не отменяют отдельно заданный флаг надёжного источника.

Документация Microsoft: [средства и параметры службы времени Windows](https://learn.microsoft.com/ru-ru/windows-server/networking/windows-time-service/windows-time-service-tools-and-settings).
